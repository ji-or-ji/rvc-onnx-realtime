# 手机链路（PHONE-LINK）：把变声送进手机

> 定位：控制台的一种**物理输出终端**，与「网络听众」并列。
> 状态：**当前主线**（2026-10-07 起）。优先级在其它探索项之前，但不设硬截止。
> 先落文档与预设，代码视真机验证结果再定。

## 一、为什么它算控制台的事

控制台的核心能力不是推理，是**把引擎的音频接到各种终端**（见 `docs/ADAPTER.md`：我们的资产是"管理"，不是"推理"）。

`AUDIO-NET.md` 解决的是"终端在网络那头"；本文解决的是"终端是一台跑着手游、输入被系统锁死的手机"。两者是同构的：

| | 网络听众（AUDIO-NET） | 手机链路（本文） |
| --- | --- | --- |
| 传输 | WebSocket PCM | 模拟音频 + USB 声卡 |
| 终端 | 浏览器（能握手、能上报） | 手机（哑终端，不能上报） |
| 引擎改动 | 只改设备选择 | 只改设备选择 |
| 方向 | 输出可多路 | 输出一路 + 一条回程 |
| 失败反馈 | 客户端能报错 | 只能人耳确认 |

**结论：它不新增引擎，不新增适配器，它新增一种路由。**

## 二、为什么必须这样绕

手游的麦克风输入被安卓锁死，理由有两条：

1. 安卓不允许第三方 App 把音频**注入**别的 App 的麦克风。非 root 无解，这是平台安全边界，不是缺 API。
   （佐证：Android 官方《共享音频输入》；Stack Overflow 37981568）
2. 安卓 10 起，两个普通应用不能同时采集音频，只有一个收到信号，另一个收到静音。这条顺手把"手机上跑转发程序"的路也堵了。

但安卓**允许外接麦克风输入**（USB 音频设备），而游戏读的是系统默认输入设备。

**所以绕法是把变声结果从物理音频通路送进手机，让游戏把它当麦克风读。** 整条链不需要 root、不需要安卓 App、不需要注入。

## 三、拓扑

```
                         ┌── 耳机（接电脑，有线优先）──┐
                         │   麦克风 ↓        ↑ 听       │
                ┌────────┴──────────────────────────┴──────┐
                │                  电脑                       │
                │   耳麦 → RVC变声 ─┬─→ 混音 ──→ 耳机         │
                │                   └─→ 输出设备 ──┐          │
                │   线路输入 ←─────────────────────┼──────────┤← 手机游戏声
                └──────────────────────────────────┼──────────┘
                                                   ▼
                                          ┌─────────────────┐
                                          │  USB 声卡        │  ← 插手机 USB-C
                                          │  麦克风输入 ←────┼── 来自电脑
                                          │  耳机输出 ──────→┼── 送往电脑
                                          └────────┬────────┘
                                                   │ 手机认成外接麦 + 外接声卡
                                                   ▼
                                            [手机 · 手游]
```

## 四、信号流

1. 声音 → 耳机麦克风（或电脑麦克风阵列）→ 电脑
2. 电脑跑 RVC 实时变声
3. 变声结果 → 引擎输出设备（= USB 声卡）→ 手机麦克风输入 → 游戏读到 → **队友听到**
4. 手机游戏声音 → USB 声卡耳机输出 → 电脑线路输入 → 混音 → 耳机（**自己听到**）
5. 可选：变声结果再分一路到耳机做监听

## 五、设计前提

- 手机是**哑终端**：不装应用、不跑推理、不参与协商。所有智能在电脑侧。
- 手机可能无 root、无 3.5mm 孔、只有 USB-C。
- 推理在电脑（有独显的那台）。
- 允许买硬件。耳机有线优先，无线可用但要接受额外延迟。

## 六、它给控制台模型带来的三样新东西

1. **输出路由的新类型：`物理终端`**，与 `网络听众` 并列。
   实现方式与网络终端同源：通过适配器的 `apply()` 设置 `sg_output_device`，引擎零改动。
2. **输入侧的新概念：`监听混音源`**。手机那条回程（游戏声）第一次让控制台需要消费一个"非引擎、非客户端"的信号，并把它混进本机监听。
3. **哑终端**：不能握手、不能上报、不能自检。这打破了 `AUDIO-NET` 里"客户端会告诉你状态"的假设，本文的失败反馈只能靠人耳。

## 七、能力缺口（现状 → 目标）

| 能力 | 现状 | 目标 |
| --- | --- | --- |
| 输出到物理设备 | 引擎自己选设备，够用但散 | 面板上一键切"手机链路" |
| 预设承载 | 预设 = 设备 + 模型 + 参数，已具备 | 加一个"手机链路"预设 |
| 硬件在位自检 | 无 | 面板检查声卡/耳机在不在，缺哪个说哪个 |
| 混音 | 无 | 游戏声 + 监听混给耳机，或明确交给 Voicemeeter |
| 终端反馈 | 浏览器能上报 | 哑终端，人耳确认，界面要明说 |

## 八、分阶段

| 阶段 | 内容 | 代码量 |
| --- | --- | --- |
| P0 | 本文 + 一个预设（输出设备指向 USB 声卡） | 零 |
| P1 | 面板加"手机链路"自检：声卡在不在、引擎输出选对没 | 小 |
| P2 | 混音与监听：游戏声 + 变声结果 → 耳机 | 中，或交给 Voicemeeter |
| P3 | 把 `物理终端` 正式并入路由模型，与 `网络听众` 统一描述 | 中，重构级 |

P0 到 P2 之间**必须先在真机验证**（见下节），验证不过就不要往 P1 投入。

## 九、风险与未验证项

1. **游戏是否接受 USB 声卡的输入作为麦克风。** 安卓一般会；真机实测。
2. **游戏是否会把播放路由到 USB 声卡。** 一般会；若不会，需要"单拾音模式"类适配器反向处理。
3. **电平匹配。** 电脑输出是线路电平（约 1V），声卡麦克风输入期望麦克风电平（约 10mV），差两个数量级，可能过载或偏小；必要时加衰减或调增益。
4. **游戏声音经电脑中转的延迟手感。** 模拟直通很小，但混音链若走软件会引入几十毫秒，要留意跟手。
5. **无线耳机的隐形税。** 游戏声多穿一层蓝牙，100~200ms 额外延迟，要手感就用有线。
6. **哑终端无反馈。** 没法用软件确认"手机真的听到了"，验证步骤必须设计成靠人耳可判。

## 十、要买的件

| 件 | 说明 | 价位 |
| --- | --- | --- |
| USB 声卡（手机端） | 免驱，USB 音频类，**同时带麦克风/线路输入 + 耳机输出** | 20~60 元 |
| USB-C OTG 转接头 | 声卡是 USB-A 口时需要 | 5~15 元 |
| 3.5mm 音频线 ×2 | 电脑输出→声卡输入；声卡输出→电脑线路输入 | 各 5~15 元 |
| 电脑端输入/输出 | 电脑自带线路输入输出优先；没有再加一个 USB 声卡 | 0~60 元 |

## 十一、验证顺序（上代码之前）

1. 接线后，**先用系统录音机**确认手机能采到电脑播放的声音（不进游戏）。
2. 再用手机上的语音 App（第三方）确认它能读到、对方能听到。
3. 最后才上游戏，确认队友能听到。
4. 每一步断了都能立刻定位，不要跳步。

## 十二、已排除

- **3.5mm 直连**：手机若无耳机孔则不适用。
- **USB 数据线跑双向音频**：数据能跑，"喂进麦克风"跑不了。
- **USB 数据线 + 手机录屏内录游戏声**：手机不装应用的约束下出局；即便装，游戏也可能禁止被采集（`ALLOW_CAPTURE_BY_NONE`）。
- **云手机 / 模拟器 / root**：都不在前提内，留档备查（各带各自代价）。

## 十三、调研来源

- Android 官方《共享音频输入》：`developer.android.google.cn/media/platform/sharing-audio-input`
- Stack Overflow 37981568（经腾讯云镜像）：不 root 无 API 可创建虚拟麦克风
- 火山引擎云手机文档「客户端内部源注入」：音频注入属于系统层能力
- CSDN《Android实现虚拟麦克风》（云手机开发者）：外源注入用于云游戏/云手机
- 实测向：安卓外接 USB 声卡用于游戏语音；外接麦克风后扬声器输出丢失及「单拾音模式」解法
