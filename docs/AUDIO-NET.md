# 网络音频（网页麦克风 / 音响）设计

**定位**：高性能网络音频（连麦、直播监听）已有成熟方案。我们**只补"没有的时候怎么办"**——所以是**监听级**，不是专业连麦级。稳，比快重要。

## 一、两条铁律（用户定）

1. **输入全局唯一**：任何时刻只允许一个输入源
2. **输出可多路**：每路**独立音量**——音量在**客户端本地**调，服务端不参与（白捡的，不用做）

## 二、输入分配：申请制 + 可抢占

- 连上后**申请**输入权（`claim`）
- 空闲 → 批准；被占 → 返回**当前持有者是谁**，界面问用户要不要抢
- **抢占**（`takeover`）→ 成功，并给原持有者发 `revoked`，它自动降级为听众
- **掉线 / 心跳超时自动释放**（心跳 3 秒；10 秒无心跳释放）
- 同一客户端重复申请 = 续期，不算抢占

> 规则已实现为 `audiohub.py`，带自检场景（`python audiohub.py`），不经网络即可验证。

## 三、音频路由（关键：**引擎零改动**）

```
输入（同时只有一个）
  浏览器麦克风 → WS → 管理台 → 写「虚拟播放端 A」
  → 引擎把输入设备选成「虚拟采集端 A」        ← 引擎以为在读本地设备
输出（可多路）
  引擎播到「虚拟播放端 B」→ 管理台读「虚拟采集端 B」
  → WS 推给所有听众；本机监听 = 同一路再写回物理输出
```

- **输入与输出必须用两对虚拟线**——同一对自己咬自己
- 没有第二对线时：输出可退化为 **WASAPI loopback**（采本机播放）
- 引擎侧只改**设备选择**一处：builtin 走 `sg_input_device/sg_output_device`；vcclient 走 `serverInputDeviceId/serverOutputDeviceId`

## 四、协议（WebSocket）

上行：`claim{label}` / `takeover{label}` / `release` / `audio{pcm}` / `ping`
下行：`granted{token}` / `denied{holder}` / `revoked{reason}` / `audio{pcm}` / `state{input,listeners}`

## 五、时延预算（监听级）

- 块长 **40–100 ms**，客户端缓冲 **2–3 块** → 端到端约 **150–400 ms**
- 明确**不追求** 20ms：那是连麦级的赛道，不是我们的

## 六、失败模式（每条都要有明确人话反馈）

- 虚拟线不存在 → 提示装 VB-Cable，并指出**缺哪一对**
- 设备被别的程序独占 → 明说**谁占用**
- 引擎没在跑 → 输入可以收，但无处可送；申请时应直接说明
- 客户端掉线 → 自动释放输入权并广播状态
