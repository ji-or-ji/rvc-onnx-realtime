# 与旧界面（RVC realtime_gui）的差距清单

写于 2026-10-02。目标：Web 面板要做到"参数不缩水 + 跟随不输旧界面"。

## 一、为什么旧界面更快、跟随更好

| 维度 | 旧界面 | 我们（当前） | 影响 |
| --- | --- | --- | --- |
| 采样长度 | 0.06 s | 0.5 s | 延迟差 8 倍，直接决定"跟不跟得上" |
| 额外推理时长 | 2.0 s | 0.25 s | 上下文小 8 倍，连贯/稳定差 |
| 响应阈值 | -55 dB | 无 | 静音不推理，算力留给说话时；"快"的隐形来源 |
| 淡入淡出 | 0.04 s | 无 | 块边界有咔哒/毛刺 |
| 后端 | torch CUDA (cu118) | ONNX-DML | DML ≈ 11~14x 实时；CUDA 才撑得住小步长+大上下文 |

结论：不是 ONNX 慢，是我把**步长做粗了**、缺**静音门限**、上下文取太小。要追平必须先把步长压到 0.1~0.15s 量级。

## 二、参数缺口（旧界面有、我们没有）

- **加载模型**：`.pth` 选择、`.index` 选择
- **音频设备**：设备类型(MME/DS/WASAPI/WDM-KS)、独占 WASAPI、使用模型/设备采样率、重载设备列表
- **常规设置**：响应阈值、音调设置、性别因子/声线粗细、检索特征占比、响度因子
- **性能设置**：采样长度、淡入淡出长度、额外推理时长、输入降噪、输出降噪

## 三、实现优先级

### P0 体验关键、成本低
- [ ] 小步长支持：默认 0.15s，范围 0.03~0.5s（引擎已支持任意 block，只是默认值粗）
- [ ] 交叉淡化（crossfade）：块边界淡入淡出，消除咔哒
- [ ] 响应阈值：输入 RMS 低于门限就跳过推理（输出静音），显著省算力
- [ ] 接通三个已有但未暴露的参数：音调(up_key)、性别因子(formant)、响度因子
- [ ] 设备侧：设备类型选择 + 独占 WASAPI 开关 + 使用模型/设备采样率

### P1 需要移植
- [ ] 检索特征占比（index 检索）：把 faiss 检索 + 特征混合移植进 ONNX 路径
- [ ] 输入/输出降噪：接 noisereduce 或 rnnoise

### P2
- [ ] `.pth`/`.index` 选择 + 自动导出 ONNX 并缓存（换模型不必手改代码）

## 四、性能前提（必须先验证）

1. 在 CUDA venv 装 `onnxruntime-gpu`，用 `--ep cuda` 复测小步长可行性
2. 基准：0.15s 步长 + 1.0s 上下文，单块耗时必须 < 150ms 才算实时
3. DML 上限决定步长下限；若 DML 追不上，就把 CUDA 作为"高跟随"模式、DML 作为"省显存"模式
