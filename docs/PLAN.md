# 计划：开箱即用骨架（S1）

目标真源见 `VISION.md`。本文件只放"怎么做、做到哪一步"。

## S1 验收标准

在一台机器上（本机即算一台）：**双击一个脚本 → 自动探测 → 自动建环境 → 取模型 → 起 WebUI**，全程无需手工敲命令。
本机已有环境，要求**检测到即复用、不重复下载**（幂等）。

## 组件分工

```
bootstrap.py      主入口：探测 → 判定 → 建环境 → 取模型 → 起服务；带状态文件、幂等、可重入
env_probe.py      探测：零依赖、只读、输出 JSON；可单独跑
recipes/*.json    配方：参数 + 模型 + 后端 + 环境要求
engines/          引擎适配层：torch 高档（参数齐）/ onnx 普及档（轻）
web/              面板（待设计 skill 后重做）
configs/config.json  参数契约（唯一真源）
```

## 判定决策表（S1a 实现）

```
NVIDIA 且 显存≥4G 且 驱动CUDA≥11.8  → 高档 torch-cuda   ~3GB   参数齐、最快
Windows 且有任意 GPU                → 普及档 ort-dml    ~300MB 轻、够用
其余                                → 保底档 ort-cpu    ~200MB 能跑、偏慢
```

附带提示：缺虚拟声卡 → 提示装 VB-CABLE；磁盘不足 → 提前告警。

## 里程碑

- M1 探测 + 判定可用（本机跑出体检报告）
- M2 bootstrap 能建环境并起服务（幂等）
- M3 配方与模型自动安装（url + sha256）
- M4 双后端引擎适配层
- M5 界面重做（等设计 skill）

## 风险与对策

- **torch 下载国内慢**：pip 镜像 + 断点续传 + 明确进度提示
- **ORT 的 CUDA/cuDNN 版本配对**：写死规则，绝不装 latest（见 VISION）
- **干净机验收成本高**：`--dry-run` + 影子目录模拟 + 状态文件回放

## 已决前提

- 平台：Windows 优先，代码留 Linux/Mac 口子
- 模型：只存链接 + sha256，不打包进仓库
- 分发：不预制，按探测结果成套下载
